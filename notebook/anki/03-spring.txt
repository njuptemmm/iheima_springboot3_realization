Spring 的两大核心是什么？	IoC（控制反转）和 AOP（面向切面编程）<br>IoC：由 Spring 容器管理对象的创建和依赖注入<br>AOP：把横切关注点（日志、事务、权限）从业务代码分离出来
IoC 和 DI 的区别？	IoC 是设计思想：对象的控制权反转给容器<br>DI（依赖注入）是 IoC 的实现方式<br>三种注入方式：<br>1. 构造器注入（推荐，@RequiredArgsConstructor）<br>2. Setter 注入<br>3. 字段注入（@Autowired，不推荐）
为什么推荐构造器注入？	1. 强制不可变（final 字段）<br>2. 依赖必填时 NPE 更早暴露<br>3. 便于单元测试（构造函数直接传 mock）<br>4. 不依赖 Spring 容器<br>本项目全部用 Lombok @RequiredArgsConstructor 实现构造器注入。
Spring Bean 的作用域有哪些？	1. singleton（默认）：容器内单例<br>2. prototype：每次 getBean 创建新实例<br>3. request：每次 HTTP 请求一个（Web 环境）<br>4. session：每次 HTTP session 一个（Web 环境）<br>5. application：ServletContext 内单例（Web 环境）
Spring Bean 的生命周期？	1. 实例化（构造函数）<br>2. 属性赋值（依赖注入）<br>3. Aware 接口回调（BeanNameAware 等）<br>4. BeanPostProcessor.before<br>5. @PostConstruct / InitializingBean.afterPropertiesSet<br>6. init-method<br>7. BeanPostProcessor.after<br>8. 使用中...<br>9. @PreDestroy / DisposableBean.destroy<br>10. destroy-method
@Autowired 和 @Resource 的区别？	@Autowired（Spring 提供）：<br>- 按类型注入<br>- 类型不唯一时按名字匹配<br>- 可加 @Qualifier 指定名字<br>@Resource（JSR-250）：<br>- 默认按名字注入<br>- 名字找不到时按类型
@Primary 和 @Qualifier 的用途？	场景：一个接口有多个实现<br>@Primary：标记某实现为默认<br>@Qualifier("beanName")：注入时指定具体的实现<br>本项目 RedisChatHistoryRepository 加 @Primary 让 Spring 默认注入它。
Spring AOP 底层实现？	两种代理：<br>1. JDK 动态代理：目标类实现接口时用，基于 Proxy.newProxyInstance<br>2. CGLIB：目标类没实现接口时用，基于生成子类<br>Spring Boot 2.0+ 默认强制用 CGLIB（proxy-target-class=true）
AOP 常用注解？	@Aspect - 切面类<br>@Pointcut - 切点<br>@Before - 前置<br>@After - 后置（finally）<br>@AfterReturning - 正常返回后<br>@AfterThrowing - 抛异常后<br>@Around - 环绕（最强大，可决定是否执行方法）
Spring 事务传播行为有哪些？	7 种（@Transactional(propagation=Propagation.XXX)）：<br>1. REQUIRED（默认）：有事务加入，没有就新建<br>2. REQUIRES_NEW：总是新建，挂起当前事务<br>3. SUPPORTS：有就加入，没有就非事务运行<br>4. NOT_SUPPORTED：挂起当前事务，非事务运行<br>5. MANDATORY：必须有事务，没有就抛异常<br>6. NEVER：不能有事务，有就抛异常<br>7. NESTED：嵌套事务（用 savepoint）
Spring 事务的隔离级别？	5 种（@Transactional(isolation=Isolation.XXX)）：<br>1. DEFAULT：跟随数据库（MySQL 默认 REPEATABLE_READ）<br>2. READ_UNCOMMITTED：读未提交（脏读）<br>3. READ_COMMITTED：读已提交（不可重复读、幻读）<br>4. REPEATABLE_READ：可重复读（幻读，MySQL InnoDB 用间隙锁避免）<br>5. SERIALIZABLE：串行化
@Transactional 什么情况下会失效？	1. 方法非 public<br>2. 类内自调用（this.methodA 调用 this.methodB，不走代理）<br>3. 抛的是**受检异常**而没配 rollbackFor（默认只回滚 RuntimeException）<br>4. 方法被 catch 了没重抛<br>5. 数据库引擎不支持事务（如 MyISAM）<br>6. 类没被 Spring 管理
Spring 事务里为什么建议 rollbackFor = Exception.class？	默认只对 RuntimeException 和 Error 回滚。<br>受检异常（IOException、SQLException 等）不会触发回滚。<br>加 rollbackFor = Exception.class 覆盖所有异常都回滚。<br>本项目 CourseTools.createCourseReservation 就是这么用的。
Spring Boot 自动配置的原理？	1. 主类 @SpringBootApplication 包含 @EnableAutoConfiguration<br>2. @EnableAutoConfiguration 通过 @Import 引入 AutoConfigurationImportSelector<br>3. 它读取 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports<br>4. 结合 @Conditional 条件加载对应的 AutoConfiguration 类<br>比如引入 spring-boot-starter-data-redis 就会加载 RedisAutoConfiguration
@ConditionalOn* 常见注解有哪些？	1. @ConditionalOnClass：类路径有某类才生效<br>2. @ConditionalOnMissingBean：容器没有某 bean 才生效<br>3. @ConditionalOnProperty：某配置存在/为某值才生效<br>4. @ConditionalOnBean：容器有某 bean 才生效<br>5. @ConditionalOnWebApplication：Web 环境才生效
Spring Boot 的 starter 是什么？	一组预先配好的依赖 + 自动配置类。<br>比如 spring-boot-starter-web 包含 Tomcat、Spring MVC、Jackson 等所有 Web 开发所需。<br>用户只需引一个依赖，配置零。<br>本项目用到：starter-web、starter-data-redis、starter-cache、starter-validation。
Spring MVC 处理请求的流程？	1. 请求进入 DispatcherServlet<br>2. HandlerMapping 找到对应的 Controller 方法<br>3. HandlerAdapter 调用方法<br>4. 参数解析（HttpMessageConverter 反序列化 body）<br>5. 方法执行返回 ModelAndView 或对象<br>6. ViewResolver 解析视图 / HttpMessageConverter 序列化响应
Spring 的循环依赖是怎么解决的？	三级缓存：<br>1. singletonObjects（完全初始化的 bean）<br>2. earlySingletonObjects（暴露的早期引用）<br>3. singletonFactories（bean 工厂）<br>Bean A 依赖 B，B 依赖 A：<br>创建 A → 提前暴露到二级缓存 → 创建 B → B 从二级缓存拿到 A 的引用 → B 完成 → A 完成<br>**只能解决单例的字段注入循环，构造器循环无法解决**。
BeanFactory 和 ApplicationContext 的区别？	BeanFactory：<br>- Spring 底层接口<br>- 懒加载（getBean 时才创建）<br>ApplicationContext：<br>- BeanFactory 的子接口，功能更多<br>- 启动时预初始化所有单例<br>- 支持事件、国际化、AOP 集成<br>日常用的都是 ApplicationContext。
@Configuration 和 @Component 的区别？	@Component：普通组件<br>@Configuration：配置类，等价于 @Component + 特殊代理<br>核心区别：<br>@Configuration 里 @Bean 方法互相调用，Spring 用 CGLIB 代理保证返回同一实例。<br>@Component 里 @Bean 方法互相调用会真的执行方法，可能创建多个实例（叫 lite 模式）。
Spring Boot Starter 是怎么打包的？	一个空的 pom.xml（没代码），只声明 dependencies。<br>加上 spring.factories 或 AutoConfiguration.imports 指向自动配置类。<br>自定义 Starter 步骤：<br>1. 建 xxx-spring-boot-starter 模块<br>2. 写 XxxAutoConfiguration<br>3. 注册到 imports 文件
Spring 里 @Async 怎么用？为什么可能失效？	使用：<br>1. 主类加 @EnableAsync<br>2. 方法上加 @Async<br>失效场景（同 @Transactional）：<br>1. 类内自调用<br>2. 方法非 public<br>3. 类没被 Spring 管理<br>推荐：自定义 TaskExecutor 而非用默认的 SimpleAsyncTaskExecutor（无线程池，每次新起线程）。
Spring 里的观察者模式：ApplicationEvent 怎么用？	1. 定义事件：class OrderCreatedEvent extends ApplicationEvent<br>2. 发布：applicationEventPublisher.publishEvent(event)<br>3. 监听：@EventListener 方法<br>可以配合 @Async 异步处理。<br>用途：解耦业务模块。
Spring Boot 默认的 Web 服务器是什么？可以换吗？	默认：Tomcat（嵌入式）<br>可换：<br>1. spring-boot-starter-web 里 exclude tomcat<br>2. 引入 spring-boot-starter-jetty 或 spring-boot-starter-undertow<br>3. 启动即用
Spring Cache 抽象的核心接口？	1. Cache（缓存实例，get/put/evict）<br>2. CacheManager（管理多个 Cache）<br>Spring Boot 根据 spring.cache.type 自动选择实现：<br>- redis: RedisCacheManager<br>- caffeine: CaffeineCacheManager<br>- simple: ConcurrentMapCacheManager
@Cacheable 的 key 支持 SpEL 表达式，常用变量？	1. #paramName - 参数名（如 #query）<br>2. #p0, #a0 - 第 0 个参数<br>3. #root.method.name - 方法名<br>4. #root.target - 目标对象<br>5. #result - 返回值（@CachePut / condition 里可用）<br>本项目：@Cacheable(value="courses", key="#query != null ? #query.toString() : 'null'")
@Cacheable、@CachePut、@CacheEvict 的区别？	@Cacheable：有缓存直接返回，无则执行方法并缓存结果（读）<br>@CachePut：无论如何都执行方法，结果放入缓存（更新）<br>@CacheEvict：删除缓存（可加 allEntries=true 清空整个 cache）<br>典型组合：读用 @Cacheable，写用 @CachePut 或 @CacheEvict。
Spring 的 @Scope("prototype") 注入到 singleton 的问题？	singleton bean 创建时依赖注入的 prototype bean 只会注入一次。<br>解决：<br>1. 用 ApplicationContext.getBean() 每次取<br>2. @Lookup 注解<br>3. ObjectProvider&lt;T&gt;<br>4. @Scope(value="prototype", proxyMode=TARGET_CLASS)
Spring Boot 里怎么定义配置文件加载优先级？	从高到低：<br>1. 命令行参数（--server.port=8081）<br>2. 环境变量<br>3. application-{profile}.yaml<br>4. application.yaml<br>5. @PropertySource 引入的文件<br>6. @SpringBootApplication 里的默认配置
Spring Boot Actuator 是什么？	监控和管理端点集合：<br>- /actuator/health - 健康检查<br>- /actuator/info - 应用信息<br>- /actuator/metrics - 指标（内存、GC、请求数）<br>- /actuator/env - 环境变量<br>- /actuator/loggers - 动态调日志级别<br>生产必备。
Spring 的 @Value 和 @ConfigurationProperties 区别？	@Value("${xxx}")：单个属性注入<br>@ConfigurationProperties(prefix="app.xxx")：对象绑定<br>推荐 @ConfigurationProperties：<br>1. 类型安全<br>2. 支持复杂结构（嵌套、集合）<br>3. 支持 JSR-303 校验<br>4. IDE 自动提示（配 spring-boot-configuration-processor）
Spring MVC 里 @RequestParam、@PathVariable、@RequestBody 的区别？	@RequestParam：URL 查询参数或 form 表单字段<br>@PathVariable：URL 路径变量 (/user/{id})<br>@RequestBody：请求体 JSON 反序列化为对象<br>本项目 /ai/chat 用 @RequestParam("prompt")，/ai/pdf/upload/{chatId} 用 @PathVariable。
Spring 全局异常处理三种方式？	1. @ExceptionHandler：单个 Controller 内的异常处理<br>2. @ControllerAdvice + @ExceptionHandler：全局<br>3. @RestControllerAdvice：等价于 @ControllerAdvice + @ResponseBody，用于 REST 服务<br>本项目 GlobalExceptionHandler 用第 3 种。
Spring 里怎么让某个 bean 只在特定 profile 生效？	@Profile("dev")<br>或 @ConditionalOnProperty(name="app.feature", havingValue="on")
